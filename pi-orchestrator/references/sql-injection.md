# SQL 注入子任务

这是静态审查参考，不授权生产请求、攻击探测或数据库写入。已有适用安全扫描工作流时遵循其前置要求和产物约定，本技能只补充 pi 的委派方式，不替代其要求。

可按仓库实际结构拆分：

- Mapper XML 与注解 SQL：追踪 `${}`、Provider 和动态表名/列名。
- Service 与查询封装：检查字符串拼接、QueryWrapper 的 `apply/last/inSql/exists` 等接受 SQL 片段的接口、原始 JDBC/JPA 查询。
- 接口与参数：从 Controller、DTO、分页排序、导出及批量入口追踪到候选 SQL，检查真实白名单和参数绑定。

不要把 `${}` 或原始 SQL API 的出现直接判为漏洞。检查片段是否固定、是否来自外部输入、转换/枚举映射是否限制取值、占位参数是否真正绑定。参数化值不能替代表名和排序字段白名单。`#{}` 通常是绑定，但仍要检查它周围的动态片段。

给 pi 的任务模板：

```text
在 <绝对仓库路径> 只读审查 <指定目录/文件> 的 SQL 注入风险。
阅读适用仓库规则。只使用 read/grep/find/ls；不联网、不运行程序、不改文件、不连接数据库，不再委派。
重点问题：<一个明确问题>。
每个候选返回：文件及行号、方法/SQL ID、外部输入来源、到 SQL 执行点的调用链、绑定/白名单证据、触发前提、信心及待核实项。
区分确认风险与搜索命中。跨出授权目录时只报告需要总管补查的符号或路径。
最后列出实际阅读的关键文件及未覆盖范围。
```

总管复核时确认路由、鉴权及调用者。鉴权只影响攻击前提，不自动消除 SQL 注入。依赖源码缺失或动态生成逻辑不可见时标为待验证，不推断安全。交付按候选归并根因，避免为同一个入口重复计数；修复优先参数绑定、固定映射和字段白名单，并给出有针对性的本地验证建议。
