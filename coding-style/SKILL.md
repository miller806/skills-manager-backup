# Coding Style

让改动像目标项目原生代码，同时保持行为、边界和历史兼容性。

## 优先级与边界

冲突时依次服从：用户要求与本次范围；`AGENTS.md` 和仓库说明；实际 formatter、编译、构建与测试配置；同模块同职责的主流写法；本技能参考。

- 风格整理不改变公开 API、序列化、数据库映射、事务、异常协议或业务语义。
- 不顺手更换框架、注入方式、工具库、语言特性或项目级质量工具；不修改生成代码。
- 只整理本次触及的代码，保留用户改动，避免批量格式化、改名、导入重排和换行符噪声。
- 仓库存在多种写法时，选择离改动最近、仍在使用且验证可行的模式，并说明必要取舍。

## 工作方式

1. 确认范围、工作区状态和仓库说明。
2. 新建、移动或重命名文件前，先查看同职责文件的命名和目录结构，确认所属模块、分层、包/命名空间及资源目录；不把文件暂放在方便但错误的位置，也不新增近义或兜底目录。
3. 检查目标模块的语言版本、依赖、构建和测试配置，并查看至少 2 个近期、同职责的邻近文件。
4. 区分硬规则与惯例，保持架构位置和外部契约后再编写或重构。
5. 检查 diff，运行与风险相称的格式、编译或测试命令；没有自动化门禁时只说明人工依据，不宣称通过了不存在的检查。

审查时优先报告缺陷、兼容风险和维护成本；纯格式问题仅在违反明确规则或造成噪声时提出，并给出文件、行号、影响与最小修正。

- 其他语言：依据目标仓库配置与邻近代码，不套用 Java 规则。
