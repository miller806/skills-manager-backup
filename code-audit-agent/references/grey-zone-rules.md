# Grey Zone Rules

**Phase**: 4  
**Previous**: Phase 3 Static Verification  
**Next**: Phase 5 Dynamic Risk Rating  
**Trigger**: 五重静态验证完成后执行

灰色地带量化评分规则。用于处理无法100%确认风险但存在明确触发条件的场景。

## 准入清单

进入灰色地带的两个条件（必须同时满足）：
1. 无法通过静态分析100%确认风险
2. 存在明确的触发条件（不是纯理论风险）

## 风险量化评分

```
风险得分 = 基础风险分 × 触发概率系数 × 业务影响系数
```

### ① 基础风险分（固定值）

| 基础分 | 漏洞类型 |
|--------|---------|
| 10分 | RCE、SQL注入、硬编码生产密钥 |
| 8分 | 命令注入、文件上传、越权访问 |
| 5分 | XSS、信息泄露、CORS错误配置 |
| 2分 | 代码规范问题、注释不规范 |

### ② 触发概率系数

| 触发难度 | 系数 | 典型场景 |
|----------|------|---------|
| 随时可触发 | 2.0 | Web根目录下可直接访问的backup.sql、注释中明文数据库密码 |
| 简单条件触发 | 1.5 | 条件编译代码（有生产环境编译选项）、死代码可通过反射调用 |
| 复杂条件触发 | 0.8 | 异步消息队列异常处理逻辑、需要特定权限才能访问的备份文件 |
| 几乎不可能触发 | 0.2 | 已废弃3年以上的模块、本地开发环境测试代码 |

### ③ 业务影响系数

| 业务上下文 | 系数 |
|-----------|------|
| 核心业务模块（支付、登录、用户信息）、公网暴露接口 | 2.0 |
| 内部业务模块、内网接口 | 1.0 |
| 工具类、测试模块、已废弃模块 | 0.5 |

## 分流处理

| 得分区间 | 级别 | 处理方式 |
|----------|------|---------|
| ≥15分 | 高风险灰色 | 自动升级为正式漏洞（Medium+），进入漏洞报告正文 |
| 5-14分 | 中风险灰色 | 保留在灰色地带，按得分从高到低排序展示 |
| <5分 | 低风险灰色 | 批量列出于附录，无需详细条目 |

## 纯静态深度分析

对中高风险灰色（≥5分），必须执行纯静态深度分析：

| 灰色场景 | 纯静态深度分析方法 |
|---------|-------------------|
| 备份文件(.bak/.sql) | Grep文件内容关键词（password/secret/key/SELECT/UPDATE）；检查是否含真实凭证或业务数据 |
| 条件编译代码 | Grep搜索编译参数定义（maven profiles/gradle buildTypes）；判断危险代码是否在默认编译参数下激活 |
| 死代码反射调用 | Grep全局搜索所有Class.forName()调用点；分析是否存在运行时激活路径 |
| 注释中的危险代码 | Grep搜索注释内危险关键词（TODO/FIXME/临时/待删除）；检查Git历史最近修改记录 |
| 字符串混淆拼接 | 执行源码级字符串常量折叠尝试；若无法完全折叠，标记为"可疑动态字符串" |
| 未启用的安全配置 | 检查配置周围代码是否有条件绕过（如profile判断逻辑） |

## 动态验证（Hybrid模式）

| 灰色场景 | 静态已有验证 | 新增动态验证 |
|---------|------------|-------------|
| 备份文件（.bak/.sql） | 检查文件是否存在 | 尝试通过HTTP访问，验证是否可直接下载 |
| 条件编译代码 | 检查条件编译指令 | 用生产环境编译参数编译项目，验证危险代码是否进入最终产物 |
| 死代码中的危险函数 | 检查直接调用 | 搜索反射调用链/动态代理/消息队列消费等间接调用 |
| 注释中的危险代码 | 检查注释内容 | 检查近3个月Git提交记录，看是否有人修改过该注释 |
| 未启用的安全配置 | 检查配置是否注释 | 尝试访问未授权接口，验证是否真的无防护 |

## 动态验证结果处理

| 验证结果 | 处理方式 |
|---------|---------|
| 验证通过（确认可触发） | 自动升级为正式漏洞（Critical/High） |
| 验证不通过（确认不可触发） | 降级为低风险提醒（<5分）或直接丢弃 |
| 无法验证（需要特定环境） | 保留在灰色地带，标注"需人工验证" |

## 特殊情况

### 高风险灰色场景
- Web根目录下的.bak/.sql/.zip备份文件
- 注释中未删除的生产密钥
- 条件编译的生产危险代码

### 中风险灰色场景
- 死代码中的危险函数
- 反射调用的动态参数（无明确用户输入）
- 未启用的安全配置

### 低风险灰色场景
- 测试文件中的危险代码
- 已废弃模块的遗留逻辑
- 注释中的TODO安全提醒

## 闭环机制

人工反馈分类：
- ✅ 确认漏洞 → 提高该类场景的基础风险分或触发概率系数
- ❌ 确认误报 → 降低系数或添加到白名单
- ⚠️ 保留灰色 → 记录特征，后续遇到类似场景优先展示

白名单机制：
- 项目级：特定文件/函数/行号添加白名单
- 规则级：某一类灰色场景添加白名单
- 有效期：默认3个月，到期自动失效
- 更新条件：若源码发生变化，白名单自动失效
